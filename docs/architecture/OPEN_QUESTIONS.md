# Ambigüedades del documento maestro

Registro sin cambiar requisitos. Resolver mediante decisiones explícitas cuando
corresponda la iteración; no inferir políticas académicas o institucionales.

| Tema / referencia | Ambigüedad | Tratamiento en Iteración 0 / siguiente paso |
|---|---|---|
| Mock y contrato (§18 vs §23) | Iteración 2 enumera contrato/Mock, pero Iteración 0 exige arrancar con Mock e incluirlo. | Stub y contrato conceptual mínimo en 0; formalización, SDK y orquestación en 2. |
| Autenticación (§8.1) | Cookies o tokens según arquitectura definitiva; faltan reglas de registro, recuperación y aprobación manual. | Resuelto en 1 mediante decisiones aprobadas: Identity, cookies Secure/HttpOnly y CSRF (ADR-012). Recuperación/confirmación quedan pendientes. |
| Versiones (§4.2, §9.2, §12, ADR-005) | Inmutabilidad tras aprobación en algunos pasajes y tras publicación en otros. | Resuelto en 5/ADR-021: Approved congela LessonVersion; Published crea disponibilidad separada. Cambios requieren nuevo borrador/versión. |
| Organización y roles (§3, §6.1, §12) | Una institución piloto, pero alcances por organización; no se define quién precarga primer admin o valida docentes. | Resuelto en 1: organización piloto fija, bootstrap explícito privado e idempotente, aprobación por Admin y pertenencia verificada (ADR-012/013). |
| Contrato IA (§11.1) | AiResponseContract, AiMessage, AiHealthResult y AiTokenUsage carecen de definición completa. | Resuelto en 2: ADR-014 fija roles, texto/JSON/subconjunto Schema, capacidades, cancelación y errores. Mock conserva solo texto; streaming futuro. |
| Privacidad (§4.1, §6.4, §14) | Falta duración de retención, efecto de revocación, base de compartición y acceso extraordinario administrativo. | En3: solo propietario, sin excepción Admin/Teacher/compartición; conservación ficticia local hasta limpieza explícita. Política real/eliminación/consentimiento siguen pendientes (ADR-016). |
| SQL del piloto (§10, §17.2) | PostgreSQL almacena la app; tema académico es SQL Server, pero falta definir evaluación aislada de T-SQL. | No instalar SQL Server ni ejecutar SQL de alumnos; definir sandbox al abordar ejercicios. |
| Terminado (§18.1) | Exige migraciones y pruebas de autorización aun cuando Iteración 0 excluye usuarios/datos. | No aplicaban a 0. En 1: migración InitialIdentity y pruebas de autorización real en PostgreSQL. |
| Plataforma y versiones (§8.1) | No se fijan Angular/PostgreSQL ni formato preciso de CI local. | ADR-011 fija versiones compatibles, scripts PowerShell y lockfiles; sin CI remoto ni publicación. |
| Alcance proveedores (§18) | Maestro reserva Gemini/Ollama como extensiones, el nuevo encargo exige integración funcional en 2. | Autorización explícita 2026-10-13, ADR-014; adaptadores probados con HTTP simulado, sin alterar fuente. |
| Schema y modelos (§11) | No se define dialecto JSON Schema ni política de actualizar modelos/capacidades. | Subconjunto explícito y catálogo conservador fechado en ADR-014; evaluar ampliaciones/modelos nuevos antes de declararlos. |
| Costos y reintentos (§11/18) | No hay presupuesto institucional ni reintentos con consumo duplicado definidos. | ADR-025 en 8: reserva persistente por intento HTTP, ventanas/día/concurrencia, tokens reportados separados de provisión, consumo incierto sin refund. No garantiza facturación/capacidad upstream ni calcula dinero sin datos. |
| Estados pedagógicos (§9.2) | Mezcla ciclo operativo con diagnóstico/enseñanza/práctica y escalamiento, sin transiciones precisas. | En 3: Created/Active/Paused/Completed y activity orientativa separada, sin Validated ni derivación ejecutada (ADR-016/017). |
| Resumen (§4/18) | Cierre de 3 pide resumen; reportes/evidencias/validadores corresponden a 4. | Resumen descriptivo local sin nueva cuota, sin calificaciones/compartición; reporte validado queda para 4. |
| Concurrencia (§13/18) | No especifica claves, recuperación de caída ni consumo cuando se pierde respuesta. | ADR-017 conserva intento durable, revisión/lease cercado y retry explícito. ADR-025 añade cuota persistente y auditoría mínima atómica; no exactly-once de facturación. |
| Ampliación de 4 | Maestro no incluye plan individual generado/ejecutado tras diagnóstico. | Nuevo encargo autoriza; ADR-018 separa PersonalizedLearningPlan de LessonVersion. No constructor docente. |
| Avance con respuestas abiertas | Sin sandbox ni juicio humano inmediato no hay verificación objetiva. | NextActivity exige respuesta; NeedsReview puede continuar expresamente, nunca significa dominio. Cerrados incorrectos requieren otro intento. |
| Reporte compartido | No está definida política institucional para dar acceso a evidencias completas. | ADR-019 implementa solo versión de reporte con consentimiento y relación vigente. Respuestas/chat no accesibles al docente; políticas reales pendientes. |
| Calidad de reglas IA | Comparador verifica coincidencia pero no validez pedagógica de clave/rúbrica. | Separar resultado Deterministic de interpretación IA, sin nota/dominio. Revisión curricular manual antes de piloto real. |
| Fiabilidad de JSON real | Declarar strict no evita todos los errores observados en Groq con estructuras anidadas. | ADR-022 simplifica DTO de transporte de clases/planes y conserva validación local; ningún fallback/reintento automático por formato. |
| Simulación frente a ejecución de clases | Motor compartido, pero resultados de ensayo no deben ser evidencia docente/estudiantil. | ADR-021: TutoringOrchestrator compartido, almacenamiento LessonSimulation/Operation separado y snapshot de revisión. No equivalencia exacta ni asignaciones de 6. |
| Retención de snapshots aprobados | Triggers impiden cambios/borrados silenciosos y no hay política institucional. | Solo ficticios locales. Borrado futuro requiere proceso/migración explícitos autorizados, sin relajar inmutabilidad durante 5. |
| Destino individual | La iteración permite incluirlo solo si no complica la seguridad. | ADR-023 concentra elegibilidad en AssignedClassAccess; 6 implementa grupo. Futura migración añadirá destinatario individual con relación de grupo verificable; no se ofrece permiso parcial. |
| Retiro de asignación/membresía | No está definido si continuar después de perder disponibilidad/relación. | ADR-023: disponibilidad retirada deja solo lectura con relación vigente; membresía/grupo/docente revocados causan 404 en cada ruta, sin borrar evidencia. |
| Entrega frente a verificación | Un ejercicio abierto no puede verificarse automáticamente de forma segura. | En clase asignada NeedsReview permite entrega/avance; cerrado exige coincidencia. Cierre local conserva pendientes humanos y versión/hash, sin nota/dominio. |
| Supervisión de clase asignada | El vínculo académico no define acceso ilimitado al chat. | Resuelto por encargo de 7/ADR-024: proyección académica para responsable vigente, sin conversación completa. Tutoría autónoma conserva propietario y compartición expresa de reporte. |
| Supervisión y pérdida de relación en 7 | ¿Co-docentes, retiro y revisiones históricas conceden lectura permanente? | ADR-024: solo responsable y cohorte vigente, sin chat; Withdrawn termina supervisión, pérdida de relación oculta historial sin borrar. Inactive/plazos/publicación archivada permiten revisar con relación vigente. |
| Revisión humana y avance | ¿Atender un caso agotado aprueba un cerrado o reinicia intentos? | No. Decisión separada, fundamentada y con historial; el comparador y sus diez intentos permanecen. Remediación/reapertura requieren futura política académica explícita. |
| Resumen cualitativo grupal | ¿Enviar respuestas personales a IA para resumir dificultades? | Diferido según prioridad permitida por el encargo de 7; panel/reportes deterministas y observaciones existentes referenciadas. Definir minimización, contratos agregados e idempotencia antes de incorporarlo. |
| Importación externa sobre borrador | ¿Reemplazar contenido existente o crear una clase nueva? | IA-1/ADR-027 importa únicamente como clase nueva tras vista previa. No acepta relaciones ni estados externos y conserva revisión/idempotencia del constructor. Reemplazo sobre borrador queda futuro. |
| Pistas externas | ¿Guardar un array nuevo de pistas? | IA-1 reutiliza hintRules textual con límite 600; la cantidad solicitada orienta las reglas. No promete un número exacto de respuestas ni cambia el motor. |
